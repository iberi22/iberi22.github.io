**১১ জুন ২০২৫, 02:05 UTC**-এ Jules আমার অ্যাকাউন্টে প্রথম push করে। সেই দিনই 03:50 UTC-এ pull request মার্জ হয়। Jules ২০ মে-র Google I/O থেকে পাবলিক বেটায় ছিল। ফিচার-সহ প্রথম পরিবর্তন ২২ মিনিট পরে আসে, সেই একই pull request-এ।

**২৮ আগস্ট ২০২৬** নাগাদ, ৮১টি রিপোজিটরিতে গোনা **11,240টি commit** নিয়ে, প্রবাহ আর চ্যাট নয়। এটি একটি **অ্যাসিঙ্ক্রোনাস, নিশ্চিত সফটওয়্যার কারখানা**, যা [Google Jules](https://jules.google)-এ **সর্বোচ্চ ১৫টি সমান্তরাল ক্ষুদ্র কাজের তরঙ্গ** পাঠায়। সমন্বয় করে **Hermes**, যাচাই করে **GitCore**-এর স্টেট মেশিন।

এই সময়টার কারিগরি পুনর্বিবেচনা: সরঞ্জাম কীভাবে বদলেছে, প্রসঙ্গের সংঘর্ষ কীভাবে এড়ানো হয়েছে, বন্ধের পরিমাপ, এবং কী শেখা গেছে।

## 1. শুরু: ন্যূনতম অবস্থান এবং প্রথম সরঞ্জাম

জুন ২০২৫ নাগাদ আমি স্থানীয় কোডিং এজেন্ট নিয়ে কাজ করছিলাম। ছেদটা ছিল Jules-এর সেই প্রথম push, কোনো IDE নয়। **Google Antigravity তখন ছিল না**: এটি বেরোয় **১৮ নভেম্বর ২০২৫**, Gemini 3-এর একই দিনে, এজেন্ট-সহ IDE হিসেবে। এই নোটের তরঙ্গ পাঠায় Jules।

কারিগরি অবস্থান এখনও ন্যূনতম:

> **ন্যূনতম ঘর্ষণের নীতি:** *যত কম সরঞ্জাম, এক্সটেনশন এবং মাঝের কনফিগ জমা করবে, তত বেশি উৎপাদনশীল হবে। কোন এডিটর, সেই তর্কে কম সময়, সমস্যায় বেশি সময়।*

সেই বসন্তে Google Labs-এর কাছে দুটি আলাদা জিনিস ছিল। **Jules** অ্যাসিঙ্ক্রোনাস এজেন্ট: একটি VM-এ রিপো ক্লোন করে pull request ফেরত দেয়। পাবলিক বেটা ছিল ২০ মে থেকে ৬ আগস্ট ২০২৫। [Google Stitch](https://stitch.withgoogle.com) ইন্টারফেস বানায়, রিপোজিটরির প্যাচ নয়। এটিও বেরোয় সেই ২০ মে।

আমরা জানতাম যে একটি সদ্য-জন্মানো প্রযুক্তিতে *early adopters* ("পরীক্ষার বিষয়") হিসেবে কাজ করছি। নিচের বাজিও স্পষ্ট ছিল: **Google আরেকটি স্থানীয় কোড-autocomplete বানাচ্ছিল না। সে গ্রহের সবচেয়ে বড় ক্লাউডকে সফটওয়্যার নির্মাণের নিচে রাখছিল।**

## 2. বাধা: গণনার বাস হিসেবে GitHub

যে প্রকৌশলী একই স্থানীয় মেশিনে ৪ বা ৫টি এজেন্ট একসঙ্গে চালিয়ে কাজ দিয়েছেন, তিনি একই ভৌত দেয়ালে ধাক্কা খান: **ফাইলের সংঘর্ষ এবং অবস্থা মুছে যাওয়া।** দুটি এজেন্ট স্থানীয়ভাবে একই ফাইল সম্পাদনা করলে কর্মক্ষেত্র নষ্ট হয়।

সেই সময়ে পথ ভার্চুয়াল ফাইল সিস্টেম ছিল না। পথ ছিল যে পাইপলাইন শিল্প আগেই সমাধান করেছিল: **GitHub**।

```

│                   PIPELINE DISTRIBUIDO DE GOOGLE JULES                 │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   GitHub Issues          Google Cloud Compute        Pull Requests     │
│  ┌──────────────┐       ┌─────────────────────┐    ┌─────────────────┐ │
│  │ Spec atómico │ ────► │ Sandbox Aislado     │ ──►│ Diff limpio +   │ │
```

প্রবাহকে **issue → আলাদা এজেন্ট-কাজ → pull request** বানালে, Jules-এর প্রতিটি ইনস্ট্যান্স Google-এর ডেটাসেন্টারে নিজের ক্ষণস্থায়ী কনটেইনারে চলে। এজেন্টরা একে অপরকে বাধা দেয় না।

এই বিচ্ছিন্নতা এই সময়ের: এক এজেন্ট, এক ব্রাঞ্চ, এক pull request। Gestalt VFS, যাতে একাধিক এজেন্ট একই ফাইল সম্পাদনা করে, পরে এসেছে। বন্ধের নিবন্ধ সেই অংশ বলে।

### ১৫টি সমবর্তী কাজের ছাদ

এই সংখ্যা ১১ জুন ছিল না। এটি আসে **৬ আগস্ট ২০২৫**, Jules বেটা ছাড়লে। Google AI Pro-তে সীমা হয় **১৫টি সমবর্তী কাজ**। ফ্রি প্ল্যান থাকে ৩-এ। তারপর থেকে তরঙ্গ এই ছাদের বিরুদ্ধে গড়ে: এক এজেন্ট একটি সীমাবদ্ধ মাইলফলক বন্ধ করে, পুরো উপ-সিস্টেম নয়।

সেই প্রকাশনায় Jules ব্যবহার করত **Gemini 2.5 Pro**। 1M-এর বেশি টোকেনের জানালা একটি crate বা একটি মডিউলের জন্য যথেষ্ট ছিল, তার টাইপ ও পরীক্ষা-সহ, যদি issue পুরো সিস্টেম হওয়ার ভান না করে।

## 3. বিশৃঙ্খলা থেকে হার্নেস: GitCore এবং ৩০ মিনিটের স্প্রিন্ট

PR বাড়লে অসঙ্গতি এল: *context drift*, কাটা নির্ভরতা, এবং অনাথ ব্রাঞ্চ। ভাগ্যের ওপর থাকা যেত না।

তখন আমি **GitCore**-এর চারপাশে ইঞ্জিনিয়ারিং হার্নেস বানাই, এবং প্রক্রিয়াটিকে **আনুষ্ঠানিক যাচাইয়ের একটি নিশ্চিত চক্র** করি:

1. **ফিচার ম্যাট্রিক্স (`features.json`):** প্রতিটি প্রকল্প তার অগ্রগতির শতাংশ এবং যাচাইযোগ্য গ্রহণ-মানদণ্ড ঠিক করে।
2. **ব্রাঞ্চের স্বয়ংক্রিয় পরিষ্কার:** প্রতিটি মার্জের পর দূরের ব্রাঞ্চের অবিরত মিল।
3. **E2E স্যুট এবং কড়া বিল্ড:** স্বয়ংক্রিয় পরীক্ষার 100% পাস না হলে কোনো PR অনুমোদিত হয় না।

```
┌──────────────────────────────────────────────────────────────────┐
│             AI SPRINT LIFECYCLE (OLEADA DE 30 MINUTOS)           │
├──────────────────────────────────────────────────────────────────┤
│  1. Lectura de estado previo en Xavier (Memoria) y features.json  │
│  2. Fragmentación en 3-4 micro-issues por feature (Islas)         │
│  3. Auditoría pre-dispatch (0 colisiones de archivos)             │
│  4. Dispatch paralelo a Jules con label 'jules' (hasta 15 tasks) │
│  5. Monitoreo asíncrono y resolución de suites de tests           │
│  6. Merge secuencial ordenado: Tipos ➔ Core ➔ API ➔ E2E          │
│  7. Actualización de métricas en features.json y cierre de sprint│
└──────────────────────────────────────────────────────────────────┘
```

সিদ্ধান্ত সঙ্গে সঙ্গে এল: **এজেন্টের একটি তরঙ্গ সাজানো ঠিক দুই সপ্তাহের অ্যাজাইল স্প্রিন্ট পরিকল্পনার মতো**, তফাত এই যে অনুমান, নির্মাণ, পরীক্ষা এবং ডেলিভারির চক্র চলে **৩০ মিনিটে**।

## 5. মূল প্যাটার্ন: ক্ষুদ্র-বিভাজন এবং অসংলগ্ন ফাইল-দ্বীপ

১৫টি সমবর্তী এজেন্ট একে অপরকে না মুছে কাজ করুক, তাই হার্নেস দুটি নিয়ম রাখে যা নড়ে না:

### A. ক্ষুদ্র-বিভাজন

কোনো issue ১৫০ লাইনের প্রভাব ছাড়ায় না, এবং দুইয়ের বেশি স্থাপত্য-স্তর ছোঁয় না। প্রতিটি বড় ফিচার ভাগ হয়:

- `[Micro-A]`: টাইপ চুক্তি, trait এবং struct।
- `[Micro-B]`: বিশুদ্ধ ডোমেন লজিক এবং অ্যালগরিদম।
- `[Micro-C]`: ইনপুট/আউটপুট অ্যাডাপ্টার (HTTP, IPC, CLI)।
- `[Micro-D]`: ইউনিট টেস্ট স্যুট এবং mock।

### B. অসংলগ্ন ফাইল-দ্বীপ

`jules` লেবেল দিয়ে তরঙ্গ পাঠানোর আগে একটি স্ক্রিপ্ট দেখে যে প্রতিটি issue-কে দেওয়া ফাইলের ছেদ একটি খালি সেট:

```python
# Verificación de Islas de Archivos Disjuntas (Pre-Dispatch QA)
islands = {
    '#issue-101': ['crates/core/src/types.rs'],
    '#issue-102': ['crates/core/src/codec.rs'],
    '#issue-103': ['crates/api/src/routes.rs'],
    '#issue-104': ['crates/core/tests/e2e_test.rs'],
}

for i1, f1 in islands.items():
    for i2, f2 in islands.items():
        if i1 < i2 and set(f1) & set(f2):
            raise SystemExit(f"❌ COLISIÓN DETECTADA: {i1} y {i2} tocan {set(f1) & set(f2)}")
print("✅ 100% Islas Disjuntas Verificadas.")
```

## 6. অবকাঠামোর ত্রয়ী: GitCore, Hermes এবং Xavier

Jules শূন্যে চলে না। পুরো বাস্তুতন্ত্রের জোড় তিনটি স্তম্ভে, যা এই কাজের জন্য বানানো:

```
                  ┌──────────────────────────────┐
                  │    XAVIER (Memoria Viva)     │
                  │  Contexto histórico & Vector │
                  └──────────────┬───────────────┘
                                 │ Context Feed
                                 ▼
┌──────────────────┐      ┌──────────────┐      ┌──────────────────┐
│  HERMES GATEWAY  │ ───► │  GITCORE CLI │ ───► │   GOOGLE JULES   │
│  Despacho Rápido │      │ State Engine │      │ 15 Parallel PRs  │
└──────────────────┘      └──────────────┘      └──────────────────┘
```

1. **GitCore:** প্রধান হার্নেস। এটি চুক্তি **1টি issue → 1টি ব্রাঞ্চ → 1টি PR** চালায়, `features.json` আপডেট করে, এবং মার্জের আগে linter চালায়।
2. **Hermes:** ডিসপ্যাচার। এটি এজেন্টের জীবনচক্র এবং কোটার সীমা সামলায়।
3. **[Xavier](https://github.com/iberi22/xavier):** স্থায়ী কগনিটিভ মেমরি, ভেক্টর অর্থ-অনুসন্ধানসহ। এটি issue-কে মাস আগের স্থাপত্য সিদ্ধান্ত দিয়ে ভরায়।

## 7. এরপর কী শক্ত করতে হবে

প্রথম push, ১১ জুন ২০২৫, থেকে প্রবাহ এই ৪ জায়গায় শক্ত হচ্ছে:

1. **CI-তে অর্থগত নিশ্চিতি:** একই তরঙ্গের ব্রাঞ্চের মধ্যে টাইপ-সামঞ্জস্য, `main`-এ মার্জের আগে।
2. **টাইমআউটের আগাম সতর্কতা:** অনুমান করা যে একটি এজেন্ট ভারী কম্পাইলে ১৫ মিনিটের বেশি কাটাবে।
3. **Xavier-এ তাৎক্ষণিক গ্রহণ:** webhook যা প্রতিটি অনুমোদিত PR-এর diff ভেক্টর মেমরিতে সূচিবদ্ধ করে।
4. **ক্ষণস্থায়ী নেটওয়ার্ক স্যান্ডবক্স:** সমবর্তী পরীক্ষা-স্যুটের জন্য সকেট ও পোর্ট আলাদা করা।

## 8. উপসংহার: প্রকৌশলের নতুন সময়

এই প্রথম বছরের সোজা শিক্ষা: **উৎপাদনশীলতার আসল লাফ autocomplete দিয়ে কোড দ্রুত টাইপ করা নয়। এটি এমন কড়া হার্নেস বানানো যা স্বায়ত্ত ঝাঁককে সমান্তরালে চালাতে পারে।**

Google Jules, Gemini-র শক্তিতে, এবং GitCore-এর মতো একটি নিশ্চিত হার্নেসে সাজানো, দেখায় যে সঠিক স্থাপত্য-সহ একজন প্রকৌশলী একটি পুরো ইঞ্জিনিয়ারিং দলের তাল, দৃঢ়তা এবং গুণে প্রকল্প চালাতে ও দিতে পারেন।
