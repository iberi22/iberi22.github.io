**11 جون 2025، 02:05 UTC** پر Jules نے میرے اکاؤنٹ میں پہلا push کیا۔ اسی دن 03:50 UTC پر pull request مرج ہوا۔ Jules 20 مئی کے Google I/O سے عوامی بی ٹا میں تھا۔ فیچر والی پہلی تبدیلی 22 منٹ بعد آئی، اسی pull request میں۔

**28 اگست 2026** تک، 81 ریپوزٹریوں میں گنے **11,240 commits** کے ساتھ، بہاؤ اب چیٹ نہیں رہا۔ یہ ایک **غیر ہم وقت، متعین سافٹ ویئر فیکٹری** ہے جو [Google Jules](https://jules.google) کو **زیادہ سے زیادہ 15 متوازی خرد کاموں کی لہریں** بھیجتی ہے۔ ہم آہنگی **Hermes** کرتا ہے، اور جانچ **GitCore** کی اسٹیٹ مشین کرتی ہے۔

یہ اس مدت کا فنی جائزہ ہے: اوزار کیسے بدلے، سیاق کی ٹکر کیسے ٹالی گئی، اختتام کے اعداد، اور کیا سیکھا۔

## 1. آغاز: کم سے کم رُخ اور پہلے اوزار

جون 2025 تک میں مقامی کوڈنگ ایجنٹ آزما چکا تھا۔ کٹاؤ Jules کے اس پہلے push پر ہوا، کسی IDE پر نہیں۔ **Google Antigravity تب تھا ہی نہیں**: وہ **18 نومبر 2025** کو آیا، Gemini 3 کے اسی دن، ایجنٹوں والا IDE بن کر۔ اس نوٹ کی لہریں Jules بھیجتا ہے۔

فنی رُخ اب بھی کم سے کم ہے:

> **کم سے کم رگڑ کا اصول:** *جتنے کم اوزار، ایکسٹینشن اور درمیانی سیٹنگیں جمع کرو گے، اتنے زیادہ پیداوار والے رہو گے۔ کون سا ایڈیٹر، اس بحث میں کم وقت، اور مسئلے پر زیادہ وقت۔*

اس موسم بہار Google Labs کے پاس دو الگ چیزیں تھیں۔ **Jules** غیر ہم وقت ایجنٹ ہے: VM میں ریپو کلون کرتا ہے اور pull request لوٹاتا ہے۔ عوامی بی ٹا 20 مئی سے 6 اگست 2025 تک رہا۔ [Google Stitch](https://stitch.withgoogle.com) انٹرفیس بناتا ہے، ریپوزٹری کا پیچ نہیں۔ وہ بھی اسی 20 مئی کو آیا۔

ہمیں معلوم تھا کہ ہم ایک نئی تکنیک پر *early adopters* ("تجربے کے موضوع") کی طرح کام کر رہے تھے۔ نیچے کی شرط بھی صاف تھی: **Google ایک اور مقامی کوڈ-autocomplete نہیں بنا رہا تھا۔ وہ سیارے کے سب سے بڑے کلاؤڈ کو سافٹ ویئر کی تعمیر کے نیچے رکھ رہا تھا۔**

## 2. رکاوٹ: حساب کی بس کے طور پر GitHub

جس انجینئر نے ایک ہی مقامی مشین پر 4 یا 5 ایجنٹ اکٹھے چلا کر کام سونپا ہے، وہ اسی طبعی دیوار سے ٹکراتا ہے: **فائل کا ٹکراؤ اور حالت کا مٹ جانا۔** دو ایجنٹ مقامی طور پر ایک ہی فائل میں ترمیم کریں تو کام کی جگہ برباد ہو جاتی ہے۔

اس مدت میں راستہ ورچوئل فائل سسٹم نہیں تھا۔ وہ پائپ لائن تھی جسے صنعت پہلے ہی حل کر چکی تھی: **GitHub**۔

```
┌────────────────────────────────────────────────────────────────────────┐
│                   PIPELINE DISTRIBUIDO DE GOOGLE JULES                 │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   GitHub Issues          Google Cloud Compute        Pull Requests     │
│  ┌──────────────┐       ┌─────────────────────┐    ┌─────────────────┐ │
│  │ Spec atómico │ ────► │ Sandbox Aislado     │ ──►│ Diff limpio +   │ │
│  │ + Criterios  │       │ (Jules Agent Run)   │    │ Tests verdes    │ │
│  └──────────────┘       └─────────────────────┘    └─────────────────┘ │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

بہاؤ کو **issue → الگ ایجنٹ کام → pull request** بنانے پر، Jules کی ہر مثال Google کے ڈیٹا سینٹروں میں اپنے مختصر کنٹینر میں چلتی ہے۔ ایجنٹ ایک دوسرے سے نہیں ٹکراتے۔

یہ علیحدگی اسی مدت کی ہے: ایک ایجنٹ، ایک برانچ، ایک pull request۔ Gestalt VFS، تاکہ کئی ایجنٹ ایک ہی فائل میں ترمیم کر سکیں، بعد میں آیا۔ اختتامی مضمون وہ حصہ بتاتا ہے۔

### 15 ہم وقت کاموں کی چھت

یہ عدد 11 جون کو تھا ہی نہیں۔ وہ **6 اگست 2025** کو آیا، جب Jules بی ٹا سے باہر نکلا۔ Google AI Pro پر حد **15 ہم وقت کام** ہوئی۔ مفت منصوبہ 3 پر رہا۔ تب سے لہریں اسی چھت کے خلاف بنتی ہیں: ایک ایجنٹ ایک محدود سنگِ میل بند کرتا ہے، پورا ذیلی نظام نہیں۔

اس اجرا میں Jules **Gemini 2.5 Pro** استعمال کرتا تھا۔ 1M سے زیادہ ٹوکن کی کھڑکی ایک crate یا ایک ماڈیول کے لیے کافی تھی، اس کی اقسام اور ٹیسٹوں سمیت، اگر issue پورے نظام ہونے کا دعویٰ نہ کرے۔

## 3. انتشار سے ہارنس تک: GitCore اور 30 منٹ کے اسپرنٹ

PR بڑھے تو بے قاعدگیاں آئیں: *context drift*، کٹی انحصاریاں، اور یتیم برانچیں۔ قسمت پر انحصار نہیں رہ سکتا تھا۔

تب میں نے **GitCore** کے گرد انجینئرنگ ہارنس بنایا، اور عمل کو **رسمی جانچ کا متعین چکر** بنا دیا:

1. **فیچر میٹرکس (`features.json`):** ہر منصوبہ اپنی پیش رفت کا فیصد اور جانچے جا سکنے والے قبولیت کے معیار طے کرتا ہے۔
2. **برانچ کی خودکار صفائی:** ہر مرج کے بعد دور دراز برانچوں کا مسلسل میل۔
3. **E2E سوٹ اور سخت بلڈ:** خودکار ٹیسٹ سوٹ کا 100% پاس ہوئے بغیر کوئی PR منظور نہیں ہوتا۔

```
┌──────────────────────────────────────────────────────────────────┐
│             AI SPRINT LIFECYCLE (OLEADA DE 30 MINUTOS)           │
├──────────────────────────────────────────────────────────────────┤
│  1. Lectura de estado previo en Xavier (Memoria) y features.json  │
│  2. Fragmentación en 3-4 micro-issues por feature (Islas)         │
│  3. Auditoría pre-dispatch (0 colisiones de archivos)             │
│  4. Dispatch paralelo a Jules con label 'jules' (hasta 15 tasks) │
│  5. Monitoreo asíncrono y resolución de suites de tests           │
│  6. Merge secuencial ordenado: Tipos ➔ Core ➔ API ➔ E2E          │
│  7. Actualización de métricas en features.json y cierre de sprint│
└──────────────────────────────────────────────────────────────────┘
```

نتیجہ فوراً آیا: **ایجنٹوں کی لہر منظم کرنا ٹھیک دو ہفتے کے ایجائل اسپرنٹ کی منصوبہ بندی جیسا ہے**، فرق یہ ہے کہ اندازہ، تعمیر، ٹیسٹ اور سپردگی کا چکر **30 منٹ** میں چلتا ہے۔

## 5. بنیادی نمونے: خرد تقسیم اور غیر متقاطع فائل جزیرے

15 ہم وقت ایجنٹ ایک دوسرے کو مٹائے بغیر کام کریں، اس کے لیے ہارنس دو قاعدے رکھتا ہے جو جھکتے نہیں:

### A. خرد تقسیم

کوئی issue 150 سطروں کے اثر سے آگے نہیں جاتا، اور دو سے زیادہ تعمیراتی تہوں کو نہیں چھوتا۔ ہر بڑا فیچر بٹتا ہے:

- `[Micro-A]`: قسم کے معاہدے، trait اور struct۔
- `[Micro-B]`: خالص ڈومین منطق اور الگورتھم۔
- `[Micro-C]`: ان پٹ/آؤٹ پٹ اڈاپٹر (HTTP، IPC، CLI)۔
- `[Micro-D]`: یونٹ ٹیسٹ سوٹ اور mock۔

### B. غیر متقاطع فائل جزیرے

`jules` لیبل کے ساتھ لہر بھیجنے سے پہلے ایک اسکرپٹ جانچتا ہے کہ ہر issue کو دی گئی فائلوں کا تقاطع خالی مجموعہ ہے:

```python
# Verificación de Islas de Archivos Disjuntas (Pre-Dispatch QA)
islands = {
    '#issue-101': ['crates/core/src/types.rs'],
    '#issue-102': ['crates/core/src/codec.rs'],
    '#issue-103': ['crates/api/src/routes.rs'],
    '#issue-104': ['crates/core/tests/e2e_test.rs'],
}

for i1, f1 in islands.items():
    for i2, f2 in islands.items():
        if i1 < i2 and set(f1) & set(f2):
            raise SystemExit(f"❌ COLISIÓN DETECTADA: {i1} y {i2} tocan {set(f1) & set(f2)}")
print("✅ 100% Islas Disjuntas Verificadas.")
```

## 6. بنیادی ڈھانچے کی تثلیث: GitCore، Hermes اور Xavier

Jules خالی جگہ میں نہیں چلتا۔ پورے ماحول کا جوڑ تین ستونوں پر ہے، جو اسی کے لیے بنے:

```
                  ┌──────────────────────────────┐
                  │    XAVIER (Memoria Viva)     │
                  │  Contexto histórico & Vector │
                  └──────────────┬───────────────┘
                                 │ Context Feed
                                 ▼
┌──────────────────┐      ┌──────────────┐      ┌──────────────────┐
│  HERMES GATEWAY  │ ───► │  GITCORE CLI │ ───► │   GOOGLE JULES   │
│  Despacho Rápido │      │ State Engine │      │ 15 Parallel PRs  │
└──────────────────┘      └──────────────┘      └──────────────────┘
```

1. **GitCore:** مرکزی ہارنس۔ یہ معاہدہ **1 issue → 1 برانچ → 1 PR** چلاتا ہے، `features.json` اپڈیٹ کرتا ہے، اور مرج سے پہلے linter چلاتا ہے۔
2. **Hermes:** ڈسپیچر۔ یہ ایجنٹوں کا حیاتی چکر اور کوٹے کی حدیں سنبھالتا ہے۔
3. **[Xavier](https://github.com/iberi22/xavier):** پائیدار علمی میموری، ویکٹر معنوی تلاش کے ساتھ۔ یہ issue کو مہینوں پہلے لیے گئے تعمیراتی فیصلوں سے بھرتا ہے۔

## 7. آگے کیا کسنا ہے

پہلے push، 11 جون 2025، کے بعد بہاؤ ان 4 جگہوں پر کسا جا رہا ہے:

1. **CI میں معنوی تصدیق:** ایک ہی لہر کی برانچوں کے درمیان قسم کی مطابقت، `main` پر مرج سے پہلے۔
2. **ٹائم آؤٹ کی جلدی خبر:** اندازہ کہ کوئی ایجنٹ بھاری تالیف پر 15 منٹ سے زیادہ لگائے گا۔
3. **Xavier میں حقیقی وقت کی انٹیک:** webhook جو ہر منظور شدہ PR کے diff کو ویکٹر میموری میں فہرست کریں۔
4. **مختصر نیٹ ورک سینڈ باکس:** ہم وقت ٹیسٹ سوٹ کے لیے ساکٹ اور پورٹ کی علیحدگی۔
